# EventLog（事记）

一个以事情为中心的 Android 本地记录 App。把预计与实际的时间、金钱、体验放在一起，留下可以回看、导出和验证的依据。

第一版使用独立包名 `com.self.daymark`，数据保存在独立的 Room 数据库中。与参考项目 Diet 互不覆盖，不需要账号，不申请网络权限。

当前版本为 **0.1.1**。英文名称统一为 EventLog；为兼容已安装应用和已有备份，包名、数据库名和 JSON 中的历史 `app: "Daymark"` 标识保留。下一版的规划与记录简化需求见 [改版计划](docs/planning-roadmap.md)，尚未包含在当前版本中。

界面采用浅蓝与白色，重点区域和新增按钮使用浅蓝底，文字保持清晰的蓝灰色。仓库包含源码、测试和数据格式说明；个人数据备份、设备截图、本机配置和编译产物不提交到 Git。

## 第一次使用

1. 按下方开发说明构建并安装 `app/build/outputs/apk/debug/app-debug.apk`，打开“事记”。
2. 在“数据 → 设置初始余额”中填写起点。金额采用人民币，先确定要追踪的账户范围，之后保持一致。
3. 在“今天 → 记一件事”中写下名称。实际用时、支出、体验都可以稍后补充；空白是未知，填 0 才表示明确为零。
4. 每天点击睡眠卡片，填写入睡、起床时间，或明确选择“没有睡眠”“时间记不清”。确认睡眠后可以确认当天记录，未确认不会阻止其他功能。
5. 提前安排的事情选“计划中”，在开始前填写预估。做完后改为“已完成”，补上实际用时和体验。
6. 定期到“数据 → 导出全部数据”保存 ZIP，可以放到电脑离线分析，也可以用它恢复数据。

不用追求全天流水账。先记录几件值得回看的事情，加上每日一次睡眠确认；预估和概率问题按需要填写。

## 五个页面

| 页面 | 第一版功能 |
| --- | --- |
| 今天 | 按日期查看事情，记录、编辑、删除事件，独立收入/支出/余额调整，睡眠确认，当天复核 |
| 日历 | 一次显示一个自然月，切换已记录净收支、活动时间、睡眠时间，点击日期进入日视图 |
| 趋势 | 最近 7 / 30 / 365 天的资金余额、收支、活动和睡眠趋势，以及按事情类别汇总的体验评分 |
| 预测 | 预计与实际的偏差、平均绝对误差、概率结果判定、Brier 分数及分组校准情况 |
| 数据 | 完整 ZIP 导出、ZIP/JSON 恢复、恢复前备份导出、带日期的资金余额起点与核对点 |

## 记录和计算约定

- **事情与流水分开。** 事件的实际费用产生一笔关联支出，修改时替换该笔支出。不要再把同一费用记成独立流水。计划金额不会扣减余额。
- **时间不重复累计。** 普通活动按时间区间取并集，跨午夜按自然日拆分；睡眠独立计算。活动时长加睡眠时长不一定等于 24 小时。
- **睡眠按起床日确认。** 日历、趋势显示的是落在自然日内的已记录睡眠时长，可能由前后两次睡眠组成。每个起床日第一版支持一段睡眠，不自动识别午睡。
- **资金余额不是完整净资产。** 起点表示所选时刻之前的余额，再加上该时刻及之后已记录的流水。新的核对点从该时刻重新计算，跳变不等于收益。账户间内部转账不要重复计入收支。
- **预估保留版本。** 每次修改预估都会新增版本。只对开始前保存、当时仍为计划且尚无完成记录的预估计分；事后补写保留为回顾。实际开始时间改到预估之前时，该预估也会失去事前资格。
- **每件事情取首份有效事前预估。** 时间、费用误差是“实际 − 预计”，正数表示低估。概率统计使用每件事情首份有效概率预测，避免反复修改让同一结果重复计分。第一版每个事件只追踪一个主要概率问题；不同问题请分开建事件。
- **概率要有判定标准和截止时间。** 截止前可以确认已经发生，但不能提前确认没有发生。Brier 是 `(p − y)²` 的平均值，发生时 `y=1`，未发生时 `y=0`。样本数量和分组结果同时展示。
- **修改后重新复核。** 事件、流水、跨日睡眠变动会取消受影响日期的确认状态。
- **删除保留部分历史。** 删除事件会移除关联流水；事件和预估历史仍在导出中以删除标记保留，不再参与统计。已移除的费用在导出中留空，不伪装成零元。

当时体验、期待的体验和“回头看是否值得”分别记录，统一使用五档评分：**−2 非常不值、−1 不值、0 中性、1 值得、2 非常值得**。未选择表示未评分，再点已选项可清空。第一版不把这些主观指标自动折算为一个总分。

0.1.1 会把已有的 1–5 分按顺序转换为 −2 到 2（原分值减 3），空值保持为空，预计与实际的评分差保持不变。旧版 JSON/ZIP 备份导入时也会转换；新版备份标为格式 2，避免重复转换。

## 导出与恢复

ZIP 中含完整的 `records.json`、分类 CSV、日汇总、预测误差以及说明文件。金额使用整数“分”，时间戳在 JSON 中为 Unix 毫秒，在 CSV 中为带时区偏移的 ISO 8601 文本。CSV 为带 BOM 的 UTF-8，适合 Excel 和 Python 读取。详细字段见 [数据说明](docs/data-format.md)。

恢复会替换当前数据，需要在 App 内确认。App 会先保存当前数据为一份本地恢复前备份，然后在数据库事务中恢复；“数据”页可导出上次恢复前备份。该备份会被下一次恢复替换。卸载会清除本机数据，请自行保管导出文件。

第一版不包含账号、联网同步、自动银行流水、自动睡眠监测、定时通知、投资估值或多币种换算。

## 开发环境

JDK 21、Gradle 8.13、Android SDK 36、Build Tools 35.0.0；Kotlin 2.2.21、AGP 8.13.2、Jetpack Compose、Room 2.8.4。最低支持 Android 8.0（API 26）。

使用 Android Studio 打开仓库，配置 JDK 和 SDK；或配置 `JAVA_HOME` 与 `local.properties` 中的 `sdk.dir`，在 Windows 执行 `./gradlew.bat assembleDebug testDebugUnitTest`，macOS/Linux 执行 `./gradlew assembleDebug testDebugUnitTest`。首次构建需要下载依赖。

原开发电脑也可在本目录执行以下本机构建辅助脚本：

```powershell
& './.tools/build.ps1'
```

脚本使用本机已有 JDK、Gradle 和依赖缓存离线构建，默认生成调试 APK 并运行单元测试。源 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。`local.properties` 的 SDK 路径以及脚本中的工具版本需要在换电脑时调整。

编译设备测试包：

```powershell
& './.tools/build.ps1' -Tasks @('assembleDebug','testDebugUnitTest','assembleDebugAndroidTest')
```

设备连接并获授权后，可用 Android Studio 或 ADB 安装主 APK 和测试 APK，运行 `com.self.daymark.test/androidx.test.runner.AndroidJUnitRunner`。数据库测试使用独立临时库，不写入正式 `daymark.db`。

测试范围和运行方式见 [测试说明](docs/testing.md)。
